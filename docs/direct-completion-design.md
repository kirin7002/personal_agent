# 简单控制：校验后直接完成

日期：2026-11-14。延续 Hermes 与分层目录架构；业务数据仍为模拟数据，不执行真实车控。

## 调用链

简单指令 → 候选 Schema 预加载 → Hermes 首次模型调用同时生成参数并声明完整覆盖目标 → 本地 Schema、版本和前置条件校验 → 原子写入完成结果与 `task.generated` 通知 → S2S 空闲时播报。

Hermes 的正式 `llm_execution` 中间件在下一次请求发出前检查数据库。若该任务已由本地校验器完成，中间件使用本地、零 token 用量的终止响应结束运行，不再请求模型确认。核心 Hermes 源码未改动；页面和测试将这次终止标记为本地完成，不计作模型调用。

这不是仅提前显示成功：真实调用计数来自中间件实际进入 `next_call` 的次数。原管理器的停止接口仍作为收尾机制，不能单独依赖 400ms 状态轮询去抢在下一轮模型请求之前停止。

## 允许直接完成的条件

全部满足才启用：

- 新任务 `completion_mode=auto`，候选预加载开启，首次任务轮次，没有追问历史。
- 本地召回只有一个控制候选，分数至少 0.82，未命中组合/查询指令检查。
- 模型在第一次回复中只提出一个 `call_tools` 调用，其中只有一个业务控制，并设置 `complete_if_success=true`，声明完整覆盖目标、没有剩余步骤。
- 中间件记录的单次工具批次摘要与真正收到的调用完全一致。并行工具响应不满足此条件。
- 没有目录浏览、额外 Schema 读取、失败、查询、追问、旧调用或额外模型请求。
- 实际调用工具与候选一致，参数、版本、模拟前置条件和结果 Schema 全部通过。

完成检查、最终结果和唯一完成通知在同一个数据库事务中提交，取消、过期轮次及重复调用不能再产生成功通知。

候选召回和 Schema 校验不能证明自然语言意图完全正确。完整覆盖目标的判断仍由第一轮模型承担；只将原来第二轮的成功确认合并进第一轮，并通过保守门槛限制适用范围。不能宣称支持所有简单指令或保证不漏语义。未满足门槛时自动保留原流程。

## 保留原流程的情况

组合操作、车书/车况查询、需要多个业务工具、参数不清楚、任何调用失败、低置信度、追问接续以及模型没有明确声明完整覆盖目标，都继续使用 `finish_task`。

例如“播放示例曲目”需要选曲加播放：即使预加载了选曲工具，也不能在选曲后提前结束。空气悬架未配备、接口未接入或行驶条件不满足时，仍查询车书/车况，返回有证据的结论或追问。

## 协议与开关

- `POST /api/tasks` 增加可选 `completion_mode: auto | agent`。`agent` 可用于对照；同一幂等键不能切换模式。
- 全局 `DIRECT_COMPLETION_ENABLED=true` 默认开启；设为 false 时新任务默认 `agent`。
- MCP `call_tools` 增加可选 `complete_if_success: boolean`，默认不声明。
- 快速完成返回 `completion.status=generated`，否则继续原处理流程。
- 使用原 `task.generated` 通知，附带已校验的调用参数；`executed=false`。
- 页面处理过程增加“校验通过，直接通知前台”，没有虚构第二次模型思考。
- `process.timing.direct_completion` 标记完成路径；`provider_requests` 是实际进入提供方调用路径的尝试数（含结束后被管理器取消的请求），不是模型输出 token 数。
- 新插件仅适配当前 `anthropic_messages` 传输。未安装插件或更换传输时，不会满足单批次凭据检查，保留正常完成流程。

安装更新使用 `scripts/configure_local_hermes.py`；启动脚本把项目模块路径和数据库绝对路径传入隔离 Hermes 环境。第三方自行启动 gateway 时也需使用相同的路径配置。

后续补充：成功结果类别可由程序按实际回执自动判定，正常多步任务完成后也可本地终止，避免无用收尾请求。详见 [结论分类设计](result-classification-design.md)。这不扩大单项控制直接完成的适用范围。

## 实测

使用同一 `deepseek-v4.1-flash-1017` 和目录，两组都启用候选预加载，仅切换完成模式。空调、车窗、媒体音量三条指令各两次，交替运行顺序：

| 模式 | 样本 | 工具/参数正确 | 中位后台耗时 |
| --- | --- | --- | --- |
| 模型确认 `agent` | 6 | 6/6 | 3.95 秒 |
| 校验后直接完成 `auto` | 6 | 6/6 | 2.17 秒 |

本次中位耗时降低 45.1%。六个 auto 样本都只进入提供方调用路径一次。agent 样本记录了三次尝试：生成参数、提交 `finish_task`，以及在管理器停止前已启动的末尾回复；末尾回复不在任务完成耗时内，且可能被取消。不能据此把旧任务说成等待了三轮完整模型响应。

七条复杂/失败/澄清/非法参数回归中，所有任务都没有使用直接完成。首轮严格断言通过 18/19 项：行驶中悬架一项返回了有证据的“等待安全驻车”追问，而脚本原先只接受终态，因此判为不通过。该追问符合原协议；脚本现同时接受已获得失败/查询证据的追问，并单独复核此场景，复核返回有证据的 `unsupported` 并通过；复核数据见 `benchmarks/results/direct-completion-driving-recheck-2026-11-14.json`。原始报告保留，不覆盖成全通过。

原始对照数据见 `benchmarks/results/direct-completion-ab-2026-11-14.json`。这些耗时不含语音识别、S2S 合成/播放或用户等待，且属于小样本测试。

## S2S 凭据

`QWEN_AUDIO_API_KEY` 可单独配置语音凭据；未设置时兼容回退到 `DASHSCOPE_API_KEY`。不改变 Hermes 的独立凭据。新 Key 若返回 `Model.AccessDenied`，页面明确展示模型权限问题；不能把 WebSocket 握手成功当成语音可用。需确认所选地域、业务空间和模型权限，参见[百炼 WebSocket 接入说明](https://help.aliyun.com/zh/model-studio/audio-realtime-websocket-access)。

验证结果：140 项自动化测试通过；真实浏览器已验证直接完成事件和一次提供方请求。新 Key 调用 Plus 返回 `Model.AccessDenied`；按用户指定切换为 `qwen-audio-3.1-realtime-flash` 后，真实语音生成验证通过。直接完成通知进入 S2S 的应用层链路及忙闲门控已由自动化测试验证。

Flash 完整链路已通过真实浏览器合成麦克风验收：Qwen 接收语音 → Hermes 一次提供方请求 → 参数校验直接完成 → Qwen 播报模拟下发成功，通知已确认送达，断开后音频资源释放正常。未录制实体麦克风，也没有执行真实车控。
