# 新需求：手机个人助理页面与电脑观察台

日期：2026-11-15｜状态：已实现手机网页与双向共享会话；浏览器/接口验收见[交付记录](mobile-sharing-acceptance.md)，实体手机仍需完成证书信任及实机确认。

本需求与正在实现的方案一第15、16节并行记录；不替代其实现与验收，不扩展方案二。

## 1. 产品目标

用户在手机上面对一个自然、简洁的个人助理：说话、打字、补充、改口、取消、查看结果和周期计划即可。电脑同时展示这段对话关联的全部可观测执行细节，用于理解 Agent 做了什么、排查问题和检查调用结构。

**一个助理、一段共享对话、同一批任务，两种展示密度。** 手机不复制桌面的调试信息，不再运行一套独立 Agent。

## 2. Muse 参考范围

用户希望手机页面全面参考 Meta Muse 的页面风格。优先采用头像/助理身份、主聊天、清晰消息气泡、简短状态、活动与计划的次级入口，以及需要时再展示操作卡片。官方设计说明了长会话、头像、活动日志、目标页和有选择的主动通知。[Muse 官方设计](https://muse.ai/blog/how-we-designed-muse)

复刻的是体验与视觉组织方式，使用本项目自己的助理名称与头像素材；不冒充 Meta 官方产品。具体配色、间距、动效属于本项目设计建议，不能把未公开的官方设计令牌当成已知数据。

## 3. 核心场景

| 场景 | 手机体验 | 电脑同时看到 |
| --- | --- | --- |
| 手机说“把空调设为23度” | 自然对话；缺分区时一句追问和主驾/全部等选项 | 用户转写、接收时间、任务关联、追问原因及工具事件 |
| 回复“全部” | 原对话继续，简短反馈 | 同一任务增加回答事件，不新建无关任务 |
| 运行中说“改成21度” | 简短确认已改目标，完成后显示21度结果 | 原目标、新目标、轮次、steer进展、旧参数拦截和有效结果 |
| 回答“算了” | 取消当前任务，一句话反馈 | 取消原因、焦点归属、停止结果与被作废通知 |
| 每天早上8点查车况 | 一张可读的计划卡片，可暂停/恢复/取消 | 计划定义、当地时区、下次触发、历次执行与跳过原因 |
| 后台有结果时用户正在说话 | 不抢话，合适时机简短播报 | 结果已就绪、等待播报、开始播放、结束/打断状态 |
| 五分钟没回答 | 显示本次请求已过期，可重新发起 | 截止时间、过期事件及旧回执/通知失效 |
| 手机掉线后重连 | 恢复对话与当前状态，不重复提交、不重播旧成功 | 同一设备/会话的重连、补发范围与投递状态 |

## 4. 手机必须展示与默认隐藏

必须展示：用户消息、助理短回复、语音输入状态、当前问题、必要选项、最终结果、失败/取消/过期说明、周期计划摘要。

默认隐藏：目录树、工具名/版本、参数Schema、JSON、模型轮数、逐步耗时、搜索候选、堆栈、运行标识和调试日志。这些保留在电脑观察台。

“查看详情”仅展开面向用户的摘要，例如“查到当前温度后生成新设置”。完整技术过程不作为手机的默认信息层级。

## 5. Personal Assistant 的回复要求

- 简短、自然、明确承接当前任务，优先说结果或下一步需要什么。
- 不逐步朗读搜索、目录和校验过程，不重复“已受理—正在处理—正在生成”等同义播报。
- 迅速完成的任务可以直接返回结果；较慢的任务给一次必要的承接反馈。
- 追问一次问清当前关键缺项，优先提供可点击选项；不让用户记任务编号。
- 前台表达可口语化，但任务状态与参数必须来自已校验事实。不能用语气替代成功证据。
- Demo 全局保留“模拟车辆”的轻提示；完成表达明确是模拟结果，不声称真实车况已改变。
- 不额外添加一个“润色 Agent”作为每次回复的必经环节；先用前台语音模型和状态模板实现。

示例：

| 情况 | 手机建议表达 |
| --- | --- |
| 缺分区 | “要调哪个位置？主驾，还是全部？” |
| 改口已登记但没完成 | “改成21度，接着处理。” |
| 模拟控制完成 | “已模拟设置：全部分区21度。” |
| 用户取消 | “好，这次不调整了。” |
| 未配备能力 | “这辆模拟车没有空气悬架，调不了车身高度。” |
| 五分钟未答 | “这次请求已过期。需要的话再告诉我。” |
| 周期任务跳过 | “这次先跳过，上一次检查还没结束。” |

## 6. 两端一致性要求

手机发送的用户消息、助理回复、任务变更和结果必须进入共享会话。电脑应实时看到用户在手机说了什么，以及对应任务的执行过程、各步骤耗时、查询证据、校验结果和最终结构。

电脑默认作为观察台，不因打开页面就重复启动语音、重新派发任务或抢走焦点。若在电脑主动输入或操作，则按同一会话的任务焦点和版本规则处理。

## 7. 范围与非目标

首版是手机浏览器页面，独立移动入口；复用现有后端和车辆模拟能力。原生App、系统后台常驻麦克风、系统级推送、车机硬件连接、真正执行车控均不包含在本次设计实现范围。

关闭网页后的后台任务可由服务继续处理，但手机网页不能承诺始终在线或自动播放。重开时同步结果；系统推送另行设计。

## 8. 验收标准（已有浏览器与接口证据，见交付记录）

1. 手机文字/语音均能创建、回答、改口和取消同一任务，沿用方案一焦点语义。
2. 手机默认不出现目录、Schema、模型轮数或JSON；电脑可查看同一次工作的完整可观测记录。
3. 两端消息、任务和结果可对应；同一句输入重试不会生成两项任务。
4. 手机的“算了”和“全部”不因桌面查看历史而改变归属。
5. 手机说话时后台结果不抢播，桌面不会把结果重复读一遍。
6. 改口/取消/过期使两端旧通知失效，迟到音频不再播放。
7. 配对后的手机和电脑属于同一对话；未配对设备不能读到这段对话。
8. 刷新或重连后文本记录可恢复，状态不会倒退；历史显示与语音已播确认分开。
9. 手机竖屏、软键盘、安全区和横竖屏切换可用；权限拒绝或断网有明确提示并保留草稿。
10. 周期计划创建、范围取消追问、暂停停止当前执行、恢复未来触发，两端状态一致。
11. 延迟断言以服务端事件为准，网页不得把等待用户或音频播放时长算成模型思考时间。
12. 语气自然但事实不变：模拟结果不能变成真实控制成功，失败不能被润色成成功。
