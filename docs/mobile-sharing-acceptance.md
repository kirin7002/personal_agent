# 手机页面与双向同步：交付与验收

日期：2026-11-15。状态：已实现并加载。车辆仍为模拟能力，方案二未修改。

## 如何连接

1. 电脑打开 `http://127.0.0.1:8765`，点击“连接手机”，生成一次性配对码。
2. 手机和电脑连接同一局域网。首次使用先打开该面板里的“HTTPS连接与信任设置”，按页面说明手动信任本机演示证书。
3. 打开面板给出的手机HTTPS地址，输入12位配对码。配对码五分钟有效，只能使用一次；新生成的码替代同设备之前的码。
4. 在任一端输入，另一端同步显示。手机保留简洁对话与结果，电脑继续展示对应任务的工具过程、耗时及JSON。
5. 语音默认由发起通话的设备播放。另一端可观察，需切换时点击“接管语音”，不能同时播放两份。

连接地址从当前项目配置生成，以电脑面板为准。Wi-Fi/IP变化后，重新运行 `scripts/configure_mobile_access.py` 并重启网页服务；CA保持不变，新的浏览器地址可能需要重新配对。

没有自动安装手机或电脑的证书信任，没有开机自启。公开下载的是CA证书，私钥只留在忽略的项目运行目录中。仅用于本机/局域网演示，不提供公网账户托管。

## 已实现范围

| 项目 | 行为 |
| --- | --- |
| 手机页面 | 独立 `/mobile` 入口；原创柔和头像、简洁聊天、问题选项、活动和周期计划；默认不展示工具树、模型轮数或JSON |
| PA表达 | 常见状态简短显示；混合结果保留查询结论，不隐藏失败原因、不把设定温度当真实车内温度 |
| 双向消息 | 两个独立设备凭据绑定同一会话；电脑发起可由手机回答，手机发起可由电脑取消 |
| 完整观察 | 桌面保留任务步骤、计时、参数和回执；手机语音转写及语音过程通过共享事件同步 |
| 历史与重连 | 消息版本更新、分页、游标补收；刷新不重复建任务，不把旧消息作为新输入 |
| 播放归属 | 一段会话只接受一个语音连接；显式接管；读取消息不会确认语音已播 |
| 设备管理 | 凭据只存哈希；配对码有时限和尝试限额；解除或重置设备后旧凭据失效 |
| 权限边界 | 远程手机必须HTTPS且完成配对才能访问任务/消息；不能借旧会话Cookie绕过设备撤销 |
| 旧结果处理 | 改口、取消、过期后的旧反馈标记失效；发送锁释放后再次检查授权，迟到数据不继续送到失效连接 |

新版从接入后持续保存对话。旧版没有保存的闲聊、原始音频或转写不能事后还原；已有任务的可观测记录和结果仍保留。

## 验收结果

- **654项自动测试通过**；一条已有Starlette/httpx弃用提示。
- **17组手机浏览器契约检查通过**，覆盖320/390/430px、输入框/页头边界、历史滚动、键盘高度、错误与草稿、配对和计划操作。
- **7组桌面共享浏览器检查通过**，覆盖消息分页/版本/重连、语音观察、配对与撤销、显式接管；无JavaScript错误。
- **真实双端页面通过**：两个独立Chrome上下文，电脑请求23度→手机回答全部→同任务完成；手机请求24度→电脑说算了→同任务取消；刷新没有重复消息。电脑看到了真实Hermes过程和最终结构。
- **真实千问共享语音通过**：文字输入/音频输出，手机设备归属正确，电脑观察到了过程，第二语音端被拒绝。
- **真实录音输入通过**：16kHz测试录音经千问转写和Hermes执行后，只有一条共享用户消息、一个任务，最终全部分区23度；桌面可观察语音过程，通知由当前语音端确认。
- **HTTPS单独校验通过**：Python客户端使用本地CA验证证书和主机名。Chrome视口自动化为便于执行使用忽略证书错误选项，这与CA校验分开记录。

实体手机和实体麦克风未参与本轮测试。需要用户在自己的iOS/Android设备上完成证书信任、麦克风授权及实机体验确认；没有把手机视口或录音输入冒充真机验收。

## 复现

```sh
uv sync --frozen
uv run python -m pytest -q
uv run python scripts/configure_mobile_access.py
uv run python scripts/start_local_services.py
uv run python scripts/validate_mobile_sharing.py
uv run python scripts/validate_shared_voice.py --audio
```

已有网页进程时需正常重启以加载地址和证书；不要另起第二个应用实例连接同一数据库。模型测试使用新测试会话，调用现有模型配置，测试车控只生成模拟结构。
