## 实现范围

- Inbox / EventRouter：接收新请求、追问回答、运行中修改、取消、排队追加、定时及外部结果事件，关联任务与轮次，事件去重。
- TaskView：有效目标、确认约束、已知工具与有效回执引用；Hermes 保留自己的 transcript。
- 原生 steer：文字和 S2S 共用改口入口；目标更新后拦截旧轮次、旧参数和旧控制回执。旧记录保留但标为被替代。
- WaitRegistry / Timers：一次定时继续；外部异步结果用测试适配器验证 pending→done/failed；用户等待复用现有问题记录。等待时不调用模型。
- ResultPolicy：Schema/目标校验、结果自动分类、重复成功控制回执复用、相同错误无新事实三次后暂停。
- Outbox：任务通知带轮次，发送前再次核对；旧通知从待播队列移除，已请求但晚到的语音/文字也被丢弃。

## 边界复查修复

- 旧 run 轮询回包提交终态前检查运行归属和任务轮次，不能把已接续的新轮次误标失败。
- 追加请求启动失败只记录该追加失败，不退出定时器调度循环。
- 修改B任务只清理B的失效播报，不截断A任务的音频或误确认A已播完。
- 不支持的复合原目标和否定改口进入澄清，不能把“不要改成21度”解释为修改到21度。
- 字段保护先尊重业务Schema；缺分区不掩盖温度范围错误，模型也不能擅自改写明确目标值。
